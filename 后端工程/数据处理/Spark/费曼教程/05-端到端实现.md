# 📌 按日订单报表端到端实现

这一篇把前面的层次落到一条最小代码链：Spring Web 创建任务，Submitter 启动独立 Spark Application，Spark 按日聚合 Iceberg 订单表，并动态覆盖目标日期分区。

示例展示责任边界和数据流。实际项目的包名、序列化、认证、异常模型和持久化实现要继承项目规范。

### 🔖 让 Spark 认识 `prod` Catalog

`prod.sales.orders` 中的 `prod` 只有在 Spark 配置里注册后才能解析。下面用通过 HTTP API 访问的 REST Catalog 说明配置形状；实际实现也可能是 Hive Metastore、JDBC、Nessie 或公司封装的 Catalog：

```properties
spark.sql.extensions=org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions
spark.sql.catalog.prod=org.apache.iceberg.spark.SparkCatalog
spark.sql.catalog.prod.type=rest
spark.sql.catalog.prod.uri=https://catalog.example.internal
spark.sql.catalog.prod.warehouse=s3://warehouse/prod
```

把这组配置放在受版本控制的 `spark-defaults.conf`、提交模板或平台 Job 模板中，并由 Submitter 选择经过审核的模板。Catalog 令牌和对象存储凭据由集群 Secret（平台受控注入的敏感配置）、工作负载身份或凭据服务注入。HTTP 请求、MQ 消息和任务表只保存非敏感任务参数。

先用隔离 Namespace 建立本教程的表结构：

```sql
CREATE NAMESPACE IF NOT EXISTS prod.spark_tutorial;

CREATE TABLE prod.spark_tutorial.orders (
    order_id STRING,
    merchant_id STRING,
    amount DECIMAL(18, 2),
    created_at TIMESTAMP
) USING iceberg
PARTITIONED BY (days(created_at));

CREATE TABLE prod.spark_tutorial.daily_order_report (
    report_date DATE,
    merchant_id STRING,
    order_count BIGINT,
    total_amount DECIMAL(28, 2),
    job_id STRING
) USING iceberg
PARTITIONED BY (report_date);
```

源表按 `days(created_at)` 做隐藏分区，查询仍然写业务列 `created_at`；Iceberg 用日期条件推导分区裁剪。结果表直接按 `report_date` 分区，因此 `overwritePartitions()` 会覆盖本次结果实际包含的日期分区。隔离验证时把 Job 参数中的输入、输出表替换为这两张练习表；通过验证后，再由受控发布配置指向 `prod.sales.orders` 和 `prod.analytics.daily_order_report`。

## 📄 第 1 步：Spring 接收并查询任务

```java
public record CreateReportJobRequest(LocalDate reportDate) {}

public record ReportJobResponse(
        UUID jobId,
        JobStatus status,
        String sparkApplicationId,
        String resultTable,
        String errorCode
) {}
```

```java
@RestController
@RequestMapping("/api/report-jobs")
@RequiredArgsConstructor
public class ReportJobController {

    private final ReportJobService reportJobService;

    @PostMapping
    public ResponseEntity<ReportJobResponse> create(
            @RequestHeader("Idempotency-Key") String idempotencyKey,
            @RequestBody CreateReportJobRequest request) {

        ReportJobResponse response = reportJobService.create(
                idempotencyKey,
                request
        );
        return ResponseEntity.accepted().body(response);
    }

    @GetMapping("/{jobId}")
    public ReportJobResponse get(@PathVariable UUID jobId) {
        return reportJobService.get(jobId);
    }
}
```

Controller 返回创建后的任务记录。它不等待 Spark 运行，也不将订单行传给 Submitter。

## 📄 第 2 步：在同一事务中写任务与 Outbox

```java
@Transactional
public ReportJobResponse create(
        String idempotencyKey,
        CreateReportJobRequest request) {

    validateReportDate(request.reportDate());

    Optional<ReportJob> existing = jobRepository
            .findByIdempotencyKey(idempotencyKey);
    if (existing.isPresent()) {
        return ReportJobResponse.from(existing.get());
    }

    UUID jobId = UUID.randomUUID();
    ReportJob job = ReportJob.pending(
            jobId,
            idempotencyKey,
            "DAILY_ORDER_REPORT",
            request.reportDate(),
            "daily-order-report:2026.08.13.1",
            "prod.analytics.daily_order_report"
    );

    jobRepository.save(job);
    outboxRepository.save(JobOutbox.sparkJobRequested(job));
    return ReportJobResponse.from(job);
}
```

数据库对 `idempotency_key` 建唯一约束，以抵抗两个并发 HTTP 请求同时通过先查。冲突后重读已有任务并返回同一 `jobId`。

## 📄 第 3 步：Submitter 只接受受控的 Job 定义

```java
public interface SparkSubmissionGateway {
    SubmittedApplication submit(ReportJob job);
    ClusterApplicationStatus getStatus(String applicationId);
    void cancel(String applicationId);
}
```

```java
public void handle(SparkJobRequested event) {
    ReportJob job = jobRepository.getRequired(event.jobId());

    if (!jobRepository.tryAcquireSubmission(job.id())) {
        return;
    }

    SubmittedApplication application = submissionGateway.submit(job);
    jobRepository.bindApplication(
            job.id(),
            application.applicationId()
    );
}
```

`tryAcquireSubmission` 是带并发条件的状态更新，例如只有 `PENDING` 且尚未绑定 Application 的记录能获取提交权。超时不确定时，Submitter 先用 `jobId` 查询集群或平台的幂等记录，再决定是否重新提交。

SparkLauncher 适配器可以这样组装受控命令：

```java
SparkAppHandle handle = new SparkLauncher()
        .setAppResource("/opt/jobs/daily-order-report.jar")
        .setMainClass("com.example.spark.DailyOrderReportJob")
        .setMaster("yarn")
        .setDeployMode("cluster")
        .setConf("spark.executor.instances", "10")
        .setConf("spark.executor.memory", "4g")
        .setConf("spark.executor.cores", "2")
        .addAppArgs(
                job.id().toString(),
                job.reportDate().toString(),
                "prod.sales.orders",
                "prod.analytics.daily_order_report"
        )
        .startApplication(listener);
```

这段代码只设置运行资源；Catalog 配置来自前面经过审核的提交模板。YARN `cluster` 模式下 Driver 由集群运行，Submitter 可以在获得 Application ID 后释放当前消费线程。不把 Listener 当成唯一状态来源。

## 📄 第 4 步：独立 Spark Job 读写 Iceberg

```java
public final class DailyOrderReportJob {

    public static void main(String[] args) {
        JobArguments input = JobArguments.parse(args);
        SparkSession spark = SparkSession.builder()
                .appName("daily-order-report-" + input.jobId())
                .getOrCreate();

        try {
            LocalDate date = input.reportDate();
            Timestamp start = Timestamp.valueOf(date.atStartOfDay());
            Timestamp end = Timestamp.valueOf(
                    date.plusDays(1).atStartOfDay()
            );

            Dataset<Row> result = spark
                    .table(input.sourceTable())
                    .filter(
                            col("created_at").geq(lit(start))
                                    .and(col("created_at").lt(lit(end)))
                    )
                    .groupBy(
                            to_date(col("created_at")).alias("report_date"),
                            col("merchant_id")
                    )
                    .agg(
                            count(lit(1)).alias("order_count"),
                            sum(col("amount")).alias("total_amount")
                    )
                    .withColumn("job_id", lit(input.jobId().toString()));

            verifySingleDate(result, date);

            result.writeTo(input.targetTable())
                    .overwritePartitions();
        } finally {
            spark.stop();
        }
    }
}
```

`JobArguments.parse` 要做严格校验：

- `jobId` 必须是 UUID。
- `reportDate` 在允许的回填窗口内。
- 表名来自受控映射或通过限定格式验证，不作为任意 SQL 片段拼接。
- 输入表与输出表不相同，且输出位于允许的 Namespace。

`verifySingleDate` 至少核对结果中 `report_date` 的最小值、最大值和非空值。该检查是一个 Action，会带来额外计算；生产实现需要根据数据量选择在主计算中合并质量指标、合理缓存，或在输出 Snapshot 后运行独立校验。

## 📄 第 5 步：Reconciler 校准结果

```text
读 report_job(J42)
  -> 用 applicationId 查集群终态
  -> 成功时查目标表日期分区和 job_id
  -> 记录可确认的 outputSnapshotId / 质量结果
  -> 带条件地将 RUNNING 更新为 SUCCEEDED
```

任务表中的 `output_snapshot_id` 是追溯信息，具体绑定方法要结合当前 Iceberg/Spark 版本可用的 Snapshot Summary、审计字段或独立运行清单设计。存在并发写者时，不用“查到最新 Snapshot”直接推断它必然属于 `J42`。

## 📄 第 6 步：做一次隔离验证

先使用隔离 Catalog、Namespace 和表名，准备三条输入：

```text
O1001, M01, 80.00, 2026-08-12 09:10:00
O1002, M01, 20.00, 2026-08-12 10:30:00
O1003, M02, 45.00, 2026-08-12 11:15:00
```

按顺序验证：

1. `POST` 返回 `PENDING` 和稳定 `jobId`。
2. Outbox 发布后，Submitter 绑定 `applicationId`。
3. Spark UI 显示扫描 Stage、Shuffle 和写入 Stage。
4. 结果表产生新 Snapshot，内容是 M01 = 2 / 100.00，M02 = 1 / 45.00。
5. 使用同一日期和幂等键重试，接口返回同一任务；主动重跑 Job 时，日报分区仍只有两行聚合结果。
6. 在写文件前、写文件后且提交 Snapshot 前、Snapshot 提交后且状态回写前分别注入失败，观察数据可见性与 Reconciler 的修复结果。
