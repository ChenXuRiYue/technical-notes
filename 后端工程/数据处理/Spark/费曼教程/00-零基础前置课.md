# 📌 先看懂 Spark 所在的数据系统

假设你已经会用 Spring Boot 查 MySQL：Controller 收到请求，Service 执行 SQL，数据库返回几百行结果。现在把数据放大到数 TB，并且要扫描一整天的订单、按商户重新分组。一台应用服务器的 CPU、内存和网络已经无法在可接受时间内完成。

Spark 解决这个计算问题：它把输入切成多份，让多个 Executor 并行处理。按商户聚合时，同一个商户的订单可能散落在不同输入分区，Spark 要按 `merchant_id` 把它们重新送到相同的后续分区。这个跨分区重新分布中间数据的过程叫 Shuffle。

## 📄 先把系统分层

| 层 | 在日报案例中负责什么 | 可观察结果 |
| --- | --- | --- |
| Spring Web | 接收日期、鉴权、创建任务、返回 `jobId` | HTTP `202 Accepted` |
| 任务库 / Outbox / MQ | 持久化任务意图，可靠传递“请执行哪份 Job” | `PENDING` 记录和任务事件 |
| Submitter | 选择 Job 产物与资源配置，提交 Spark Application | `applicationId` |
| 集群管理器 | 在 YARN、Kubernetes 或 Standalone 上分配 Driver 和 Executor 资源 | Application 运行状态 |
| Spark | 解析计算、拆分 Task、并行执行 | Stage、Task、读写量、Shuffle 指标 |
| Iceberg Catalog | 用表名定位当前元数据，协调新版本提交 | Metadata JSON 入口 |
| Iceberg 表 | 记录 Schema、Snapshot 和有效文件集合 | 输入与输出 Snapshot |
| S3 / OSS / HDFS | 持久保存元数据与 Parquet 等文件的字节 | 对象或文件 |

这张表里的“任务”有多个层次。业务任务用 `jobId` 跟踪，集群运行用 `applicationId` 跟踪，Spark 内部还会产生 Job、Stage 和 Task。名称相似，身份和生命周期不同。

## 📄 Spark 与 MySQL 的交集

Spark SQL 和 MySQL SQL 共享 `SELECT`、`WHERE`、`GROUP BY`、`JOIN` 等 SQL 主干。各自的方言、运行方式和数据组织不同：

| 问题 | MySQL | Spark SQL + Iceberg |
| --- | --- | --- |
| 谁解析 SQL | MySQL Server | Spark SQL 与 Iceberg Runtime |
| 谁执行计算 | MySQL Server 内的线程 | Driver 规划，Executor 并行执行 |
| 表保存在哪里 | InnoDB 数据页与索引 | Iceberg 元数据管理的数据文件 |
| 一次查询的常见时间 | 毫秒到秒 | 秒到小时，取决于数据量与计算 |
| 主要工作负载 | OLTP 点查、单行事务 | OLAP 扫描、批量聚合、回填 |

因此，会写 MySQL SQL 能帮你快速表达计算，但还要学会判断文件扫描、分区数、Shuffle 数据量和集群资源。

## 📄 五个基础词

### 🔖 有界数据与批处理

一天订单有确定的开始和结束，因此是**有界数据**。Spark 可以读完这个范围、产生结果后退出，这是典型**批处理**。

Spark Structured Streaming 处理持续到来的无界数据。它把新到数据按 Trigger（触发节奏）推进，使用 Checkpoint（持久化进度与恢复信息）和状态存储支持故障恢复。日报先采用有界批处理，因为输入范围和完成条件都能直接观察；持续流任务还要继续学习事件时间、迟到数据和 Sink 提交语义。

### 🔖 ETL

ETL 是 Extract、Transform、Load：读取输入，转换和校验，再写入目标。在本教程中：

```text
Extract：读 prod.sales.orders
Transform：按日期过滤，再按 merchant_id 聚合
Load：写 prod.analytics.daily_order_report
```

### 🔖 Partition

Spark Partition 是一份并行计算输入，通常对应一个 Task。Iceberg Partition 是表的数据布局规则，用于组织和裁剪文件。一个 Iceberg 分区可以包含多个数据文件，这些文件又可以被 Spark 规划成多个扫描 Task。

### 🔖 Cluster Manager

集群管理器分配 CPU 和内存，并在节点上启动 Driver 与 Executor。YARN、Kubernetes 和 Spark Standalone 都可承担这个角色。

### 🔖 Application

一次 `spark-submit` 通常创建一个 Spark Application。Application 内有一个 Driver 和若干 Executor，一次运行可以因多个 Action 产生多个 Spark Job。

## 📄 先预测

Spring 已经返回：

```json
{"jobId":"J42","status":"PENDING"}
```

此时可以确定的事只有：日报请求已被接受，并在 Spring 任务体系中获得稳定身份 `J42`。`applicationId` 可能还未创建，Executor 可能尚未启动，输出 Snapshot 也尚未提交。

改变一个条件：状态已是 `RUNNING`。这说明集群中的 Application 已经开始运行，仍不证明结果表已经发布新 Snapshot。

画七个方框：Spring、任务库、Submitter、Cluster Manager、Spark、Iceberg、对象存储。把下面的动作放到负责方框中：

- 校验 `reportDate`
- 分配 Executor 内存
- 用表名找到 Metadata JSON
- 扫描 Parquet
- 创建 `jobId`
- 发布新 Snapshot
- 保存 Parquet 字节
