# 📌 先看懂文件系统、FUSE 与对象存储

上传服务执行 `open("/srv/media/inbox/M1001.mp4")` 时，它只交出一个路径。系统必须回答：这个路径指向哪个文件、调用者有没有写权限、文件有多长、内容位于哪里。JuiceFS 把这些答案分给元数据引擎、对象存储和客户端处理。

学完本篇，你应该能把一次路径访问拆成“查名字与属性”和“读写字节”两类动作，并解释 FUSE 为什么能让用户态程序实现文件系统。

## 📄 路径怎样找到文件

文件系统把一串路径名解析为一个文件对象。以 `/srv/media/inbox/M1001.mp4` 为例：

```text
/ -> srv -> media -> inbox -> M1001.mp4
```

目录中的“名字到文件身份的映射”称为目录项。Unix/Linux 文件系统常用 inode 表示文件身份；inode 记录类型、权限、大小、时间等属性。文件名属于目录项，同一个 inode 可以通过硬链接拥有多个名字。

因此，重命名主要改变目录项；读取内容还要继续找到文件对应的数据。已有的 [软链接与 inode](../../../../专业基础/操作系统/软链接.md) 对本地文件系统模型有更完整的解释。

## 📄 系统调用与 POSIX 接口

应用通常不直接操作磁盘，而是调用操作系统提供的文件接口：

| 动作 | 常见系统调用 | 要解决的问题 |
| --- | --- | --- |
| 打开 | `open` | 路径是否存在、权限是否允许、返回哪个文件描述符？ |
| 读取 | `read` | 从指定偏移取多少字节？ |
| 写入 | `write` | 从指定偏移写入哪些字节？ |
| 持久化 | `fsync` | 已写内容何时达到持久化边界？ |
| 改名 | `rename` | 目录树中的名字怎样原子切换？ |
| 查看属性 | `stat` | 文件大小、权限、所有者、修改时间是什么？ |

POSIX 是一组操作系统接口与行为约定。说 JuiceFS“兼容 POSIX”，表示常见程序可以通过熟悉的文件 API 使用它。具体支持范围仍受 FUSE、操作系统和 JuiceFS 实现影响，上线前要用目标应用验证 [官方兼容性清单](https://juicefs.com/docs/community/posix_compatibility)。

## 📄 挂载点做了什么

挂载把一个文件系统接入现有目录树。挂载完成后，访问 `/srv/media` 的请求交给 JuiceFS；访问 `/var/log` 仍由原来的本地文件系统处理。

```text
Linux 根目录树
├── var/log       -> 本地 ext4 或 XFS
└── srv/media     -> JuiceFS
```

挂载点只是入口。它不表示 JuiceFS 的全部数据都保存在 `/srv/media` 所在磁盘。

## 📄 FUSE 为什么能运行在用户态

FUSE 全称 Filesystem in Userspace。内核负责接收应用的系统调用，再通过 FUSE 接口把文件请求转交给用户态的 JuiceFS Client：

```text
应用 open/read/write
        |
        v
操作系统 VFS + FUSE
        |
        v
JuiceFS Client 进程
```

VFS（Virtual File System，虚拟文件系统）是内核中的统一文件接口层。应用只调用 `open`，VFS 根据路径属于哪个挂载点，把请求路由给相应文件系统。

用户态实现便于跨平台开发、升级和接入远程服务。边界是每次请求要经过内核与用户态之间的交互，行为也受到 FUSE 能力限制。

## 📄 对象存储提供什么

对象存储使用 Bucket 和对象键保存字节。例如：

```text
s3://media-prod/chunks/0/12/12345_0_4194304
```

它擅长通过网络 API 保存大量对象、独立扩容和提供高持久性。对象接口通常围绕 PUT、GET、HEAD、DELETE 和 LIST 展开，不天然提供完整的 POSIX 目录、inode、文件锁和随机覆盖写语义。

JuiceFS Client 把文件内容切成 Block 后写入对象存储；路径、权限和“文件偏移对应哪些 Block”的信息写入元数据引擎。这样，对象存储负责数据容量，数据库负责共享文件系统的组织与协调。

## 📄 元数据与数据

| 类别 | `M1001.mp4` 中的例子 | JuiceFS 保存位置 |
| --- | --- | --- |
| 元数据 | 文件名、inode、大小、权限、mtime、锁、Chunk/Slice 映射 | 元数据引擎 |
| 数据 | 视频文件的实际字节 | 对象存储中的 Block |

mtime 是 modification time，表示内容最后修改时间。Chunk、Slice、Block 是 JuiceFS 的数据组织术语，将在 [架构与读写路径](01-架构与读写路径.md) 中用同一个文件解释。

元数据通常远小于文件数据，却决定对象怎样重新组成目录和文件。只保住对象存储而丢失元数据，就像保住所有散页却丢失目录、页码和装订关系。

## 📄 本地缓存位于哪里

每个 JuiceFS Client 可以使用本机磁盘缓存对象存储 Block。缓存命中时，读取少走一次远程网络；缓存未命中时，客户端从对象存储下载，再按配置放入本地缓存。

缓存是一份可重建的读取副本。默认可靠写入仍以对象存储和元数据提交为持久化依据。开启客户端写回缓存后，本地暂存数据在上传完成前不可重建，因此风险边界会改变。

## 📄 单位先统一

本教程使用二进制容量单位：

| 单位 | 字节数 | 常见用途 |
| --- | ---: | --- |
| KiB | 1,024 | 小文件和小请求 |
| MiB | 1,048,576 | Block、缓存和带宽 |
| GiB | 1,073,741,824 | 大文件、磁盘和内存 |

网络服务商有时使用十进制 MB/GB。做容量与吞吐计算时先确认监控面板采用哪套单位。
