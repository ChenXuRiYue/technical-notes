# 📌 从零跑通本地 JuiceFS

这一篇在一个隔离目录中创建完整的 JuiceFS：SQLite 保存元数据，普通本地目录模拟对象存储，FUSE 把文件系统挂载到 `mount/`。实验不需要云账号、Redis 或 Kubernetes。

学完后，你应该能亲自观察“挂载点中的文件名”和“底层 Block 对象”不是同一种组织方式，并能用 `status`、`info` 验证元数据与数据映射。

## 📄 第 0 步：确认环境

适用环境是 Linux 或 macOS。需要：

- 已安装 JuiceFS Community Edition 客户端。
- Linux 已安装并允许使用 FUSE；macOS 已安装当前 JuiceFS 文档要求的 FUSE 组件。
- 当前用户能在实验目录中创建文件和挂载点。

先检查：

```bash
juicefs version
juicefs mount --help
```

若未安装，官方当前提供下面的安装入口：

```bash
curl -sSL https://d.juicefs.com/install | sh -
```

安装脚本会随当前发行版变化。生产环境应从 [安装文档](https://juicefs.com/docs/community/getting-started/installation) 选择固定版本、校验制品，并经过内部供应链审核；不要把无版本锁定的一键脚本直接放入生产镜像。

## 📄 第 1 步：建立隔离目录

在你准备做实验的目录执行：

```bash
mkdir -p juicefs-lab/mount juicefs-lab/cache juicefs-lab/objects
cd juicefs-lab
export JFS_LAB_DIR="$PWD"
```

三个目录分别承担：

| 路径 | 职责 |
| --- | --- |
| `mount/` | 应用看到的 JuiceFS 挂载点 |
| `cache/` | 客户端本地 Block 缓存 |
| `objects/` | 实验中的底层数据存储 |

SQLite 文件 `metadata.db` 会在当前目录创建。这个实验把所有状态集中到 `juicefs-lab/`，便于观察，也避免和其他 JuiceFS 卷混在一起。

## 📄 第 2 步：格式化文件系统

```bash
juicefs format \
  --storage file \
  --bucket "$JFS_LAB_DIR/objects" \
  --trash-days 1 \
  sqlite3://metadata.db \
  media-lab
```

`format` 写入一个新文件系统的固定配置：名称、UUID、底层存储、Block 大小、回收站天数等。它不会把挂载点接入目录树。

输出随版本不同，但应该包含类似信息：

```text
Meta address: sqlite3://metadata.db
Data use file:///.../juicefs-lab/objects/
Volume is formatted as {Name:media-lab ... Storage:file ...}
```

检查文件：

```bash
ls -lh "$JFS_LAB_DIR/metadata.db"
juicefs status "sqlite3://$JFS_LAB_DIR/metadata.db"
```

`status` 应返回卷名、UUID、存储类型、Bucket 和当前会话。此时还没挂载，所以活动挂载会话可能为空。

## 📄 第 3 步：先预测再挂载

预测下面命令完成后，哪个目录会直接出现 `inbox/M1001.txt`：`mount/` 还是 `objects/`？

```bash
juicefs mount -d \
  --cache-dir "$JFS_LAB_DIR/cache" \
  "sqlite3://$JFS_LAB_DIR/metadata.db" \
  "$JFS_LAB_DIR/mount"
```

检查挂载：

```bash
df -h "$JFS_LAB_DIR/mount"
juicefs status "sqlite3://$JFS_LAB_DIR/metadata.db"
```

现在 `status` 应显示本机挂载会话。`-d` 表示客户端转入后台运行。

## 📄 第 4 步：写入并读回

```bash
mkdir -p "$JFS_LAB_DIR/mount/inbox" "$JFS_LAB_DIR/mount/review"

printf 'media-id=M1001\nstatus=uploaded\n' \
  > "$JFS_LAB_DIR/mount/inbox/M1001.txt"

cp "$JFS_LAB_DIR/mount/inbox/M1001.txt" \
  "$JFS_LAB_DIR/mount/review/M1001.txt"

cat "$JFS_LAB_DIR/mount/review/M1001.txt"
cksum "$JFS_LAB_DIR/mount/inbox/M1001.txt" \
      "$JFS_LAB_DIR/mount/review/M1001.txt"
```

期望 `cat` 输出：

```text
media-id=M1001
status=uploaded
```

两行 `cksum` 的校验值与字节数应相同，说明从挂载点读回的内容一致。

## 📄 第 5 步：观察内部映射

```bash
juicefs info "$JFS_LAB_DIR/mount/inbox/M1001.txt"
find "$JFS_LAB_DIR/objects" -type f | sed -n '1,20p'
find "$JFS_LAB_DIR/cache" -type f | sed -n '1,20p'
```

`juicefs info` 会显示 inode、长度、路径以及文件对应的对象信息。底层 `objects/` 中出现的是 JuiceFS 内部组织的 Block，不是 `inbox/M1001.txt` 这棵业务目录。

回看第 3 步的预测：

- `mount/inbox/M1001.txt` 是通过元数据映射呈现的逻辑路径。
- `objects/` 保存数据 Block。
- `metadata.db` 保存目录树、属性和 Block 映射。
- `cache/` 保存客户端可重建的本地缓存。

小文件的具体对象形状受客户端缓冲、Block 大小和当前版本影响，不要把一次 `find` 的对象数量当成固定协议。

## 📄 第 6 步：验证改名不重写内容

先记录对象文件列表：

```bash
find "$JFS_LAB_DIR/objects" -type f | sort > /tmp/jfs-objects-before.txt
mv "$JFS_LAB_DIR/mount/inbox/M1001.txt" \
   "$JFS_LAB_DIR/mount/inbox/M1001-renamed.txt"
find "$JFS_LAB_DIR/objects" -type f | sort > /tmp/jfs-objects-after.txt
diff /tmp/jfs-objects-before.txt /tmp/jfs-objects-after.txt
```

通常 `diff` 没有输出，因为改名更新目录元数据，不要求重写文件 Block。后台任务与实现细节可能让观察目录出现其他变化，因此最终证据还应结合 `juicefs info`：改名前后文件内容映射保持一致，逻辑路径发生变化。

## 📄 第 7 步：安全结束实验

```bash
juicefs umount "$JFS_LAB_DIR/mount"
juicefs status "sqlite3://$JFS_LAB_DIR/metadata.db"
```

确认挂载会话消失后再关闭终端。教程不自动删除 `juicefs-lab/`，因为 `metadata.db` 与 `objects/` 共同构成可继续观察的实验文件系统。需要清理时，先确认挂载已卸载，并人工核对目标目录只包含本实验数据。

## 📄 分层排错

按执行顺序检查：

1. `juicefs: command not found`：回到第 0 步检查安装路径。
2. FUSE 或权限错误：确认系统已安装 FUSE、当前用户有挂载权限，检查客户端日志。
3. `database is locked`：确认没有把 SQLite 元数据文件交给多个独立主机或不兼容进程并发访问。
4. Bucket 路径权限错误：检查 `objects/` 的所有者和读写权限。
5. 写入成功但实验结果不符：运行 `juicefs info` 与 `juicefs status`，不要直接修改 `metadata.db` 或内部 Block。

本教程环境没有预装 JuiceFS 与 FUSE，因此上述命令已按 2026-08-27 的官方 Community Edition 文档核对，但未在当前工作区实际挂载执行。

## 📄 费曼复述

不用“分布式”这个词，向同事解释四个实验路径各保存什么：`mount/`、`cache/`、`objects/`、`metadata.db`。如果把 `cache/` 说成唯一数据副本，回到第 5 步重看各自的持久化职责。
